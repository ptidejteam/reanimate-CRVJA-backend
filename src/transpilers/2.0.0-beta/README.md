# AMOS → JavaScript transpiler 2.0.0-beta: developer tutorial

This tutorial explains how the 2.0.0-beta transpiler is organized and walks you through
adding or changing an AMOS command. All new work happens in this version; `1.1.0` and
`1.2.0` are kept unchanged for older programs.

## 1. How the transpiler works

```
AMOS source code
  │  transpiler.js
  ▼
ANTLR lexer + parser   (grammar/amos.g4, compiled into grammar/generated/)
  │  parse tree
  ▼
AmosTranslator         (amos-translator.js)
  │  ANTLR calls enterX(ctx) / exitX(ctx) for every grammar rule X it walks through.
  │  The forwarder for X calls the method with the same name in commands/<category>.js,
  │  which appends JavaScript to the program with this.emit(...).
  │
  │  Expressions (X + Rnd(6)) are translated by ExpressionVisitor (expression-visitor.js);
  │  AMOS functions are forwarded from there to commands/functions.js the same way.
  ▼
prettier formats the program (runtime/amos-runtime.js is included in it)
  ▼
JavaScript that runs in the browser
```

| Path                       | What it contains                                                                                 |
| -------------------------- | ------------------------------------------------------------------------------------------------ |
| `transpiler.js`            | Entry point: parse, translate, format. Returns `{ lexicalErrors, syntaxErrors, translatedCode }` |
| `grammar/amos.g4`          | The AMOS grammar: parser rules grouped by category, A-Z                                          |
| `grammar/generated/`       | Generated by ANTLR from `amos.g4`. **Never edit by hand**                                        |
| `amos-translator.js`       | Translation state, helpers, and one forwarder per command (by category, A-Z)                     |
| `expression-visitor.js`    | Expressions (operators, parentheses, arrays) and the forwarders for functions                    |
| `commands/`                | The translation of every command, one file per category                                          |
| `commands/base-handler.js` | Helpers every command file inherits: `emit`, `expr`, `declareVariable`                           |
| `runtime/amos-runtime.js`  | JavaScript included in every generated program (colours, keyboard, sound, sprites, files…)       |
| `error-listener.js`        | Collects the lexical and syntax errors                                                           |

## 2. Where is a command?

Every AMOS command lives in one place, decided by its **category**: the `CATEGORY` column of
the tracking spreadsheet (`CRVJA - AMOS Basic Tracking.xlsx`), which follows the official
[AMOS Professional command index](https://amospromanual.dev/99-appendix-g-command-index.html).

1. Look the command up in the spreadsheet and read its category, e.g. `PALETTE` → Instruction.
2. The file is the category in kebab-case plural: `commands/instructions.js`.
3. Inside the file, commands are sorted **A-Z by AMOS name**. Each starts with a marker that
   links to its documentation:
   ```js
   // ---- PALETTE: https://amospromanual.dev/06-04-graphics.html#i-palette ----
   enterPalette(ctx) {
   ```
4. The same name, at the same A-Z position, appears in two more places:
   - `grammar/amos.g4`, under the category heading, as `// PALETTE` above the rule;
   - the forwarder, as `// PALETTE` above it: in `amos-translator.js` for instructions and
     structures, in `expression-visitor.js` for functions.

To find a command in the code, search for its name in capitals, e.g. `// PALETTE`. Method
names come from the grammar rule, not from the AMOS name (`DIM` → `enterArrayDeclaration`,
`LOAD` → `enterLoadBank`), so the comment is the reliable way to find it.

| Category                           | File in `commands/` | Forwarded from          | Translated today                                                                                                                                           |
| ---------------------------------- | ------------------- | ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Instruction                        | `instructions.js`   | `amos-translator.js`    | ADD, BAR, BOX, CIRCLE, CLOSE, CLS, CURS OFF, CURS ON, DIM, INK, LOAD, OPEN IN, OPEN OUT, PALETTE, PAPER, PEN, PLAY, PRINT, SCREEN OPEN, SPRITE, TEXT, WAIT |
| Structure                          | `structures.js`     | `amos-translator.js`    | DATA, DO…LOOP, ELSE, FOR…NEXT, GLOBAL, IF…END IF, IF KEY STATE, INPUT #, PROC, PROCEDURE…END PROC, READ, REPEAT…UNTIL, WHILE…WEND, assignments             |
| Function                           | `functions.js`      | `expression-visitor.js` | COS, RND, SIN                                                                                                                                              |
| AMCAF extension (not in the index) | `amcaf.js`          | both                    | BLITTER CLEAR, BLITTER FILL, QCOS, QSIN, TURBO DRAW                                                                                                        |

The other categories have no translated command yet. Their file is created, with the same
naming rule, when the first command is implemented
([section 5](#5-the-first-command-of-a-new-category)):

- Interface Instruction, Interface Function, Interface Structure → `interface-instructions.js`,
  `interface-functions.js`, `interface-structures.js`
- AMAL Instruction, AMAL Function, AMAL Structure → `amal-instructions.js`, `amal-functions.js`,
  `amal-structures.js`
- Embedded Menu Command → `embedded-menu-commands.js`
- Reserved Variable → `reserved-variables.js`
- System Function → `system-functions.js`
- Picture Compactor Extension → `picture-compactor-extension.js`

**Edge cases** (each one is also explained by a comment in the code):

- `PRINT #` is a Structure, but it shares the grammar rule of `PRINT`, so it is translated in
  `instructions.js` under `PRINT`.
- `KEY STATE` is a Function, but the grammar only accepts it as the condition of `If` / `While`,
  so it is translated in `structures.js` under `IF KEY STATE` and `WHILE`.
- Variable and array assignments (`X = 1`, `A(1) = 2`) and labels have no category. They are at
  the end of `structures.js` and of the Structures part of `amos.g4`, under _Not in the command
  index_.
- Commands that are not in the index come from an extension (today only AMCAF) and go in that
  extension's file.

## 3. Tutorial: add an instruction (`PLOT`)

Goal: support `Plot x,y`, which draws a point. The spreadsheet says: `PLOT`, category
Instruction, documented at `https://amospromanual.dev/06-04-graphics.html#i-plot`. So it goes in
`commands/instructions.js`, and alphabetically between `PLAY` and `PRINT` everywhere.

### Step 1: grammar

In `grammar/amos.g4`, under `// ---- Instructions ----`, between `// PLAY` and `// PRINT`:

```antlr
// PLOT
plot:
    'Plot' expression COMMA expression
    ;
```

Then add the rule at the **end** of the `statement:` alternatives:

```antlr
    | screenSwap
    | plot
    ;
```

ANTLR resolves ambiguities in favour of the alternative listed first, so appending keeps the
behaviour of the existing commands.

### Step 2: regenerate the parser

From the backend root (Java must be installed):

```bash
npm run compile-grammar
```

This rewrites `grammar/generated/` (commit those files too). The parser now has a rule `plot`,
so the translator will receive `enterPlot(ctx)` calls.

### Step 3: forwarder

In `amos-translator.js`, in the Instructions section, between `// PLAY` and `// PRINT`:

```js
  // PLOT
  enterPlot(ctx) {
    this.instructions.enterPlot(ctx);
  }
```

### Step 4: translation

In `commands/instructions.js`, between `PLAY` and `PRINT`:

```js
  // ---- PLOT: https://amospromanual.dev/06-04-graphics.html#i-plot ----
  enterPlot(ctx) {
    const x = this.expr(ctx.expression(0));
    const y = this.expr(ctx.expression(1));

    this.emit(`
{
const plotDiv = document.createElement('div');
plotDiv.style.position = 'absolute';
plotDiv.style.left = (${x}) + 'px';
plotDiv.style.top = (${y}) + 'px';
plotDiv.style.width = '1px';
plotDiv.style.height = '1px';
plotDiv.style.backgroundColor = getColour(Ink);
document.getElementById('amos-screen').appendChild(plotDiv);
}`);
  }
```

- `ctx` is the parse-tree node of the rule. `ctx.expression(0)` is the first `expression` of
  `'Plot' expression COMMA expression`, `ctx.expression(1)` the second.
- `this.expr(...)` turns an AMOS expression into JavaScript (`X+1` → `X + 1`).
- `this.emit(...)` appends code to the generated program. That code can use everything defined
  in `runtime/amos-runtime.js`, such as `getColour` and the current `Ink`.

### Step 5: test

Create `tests/plot.spec.js`:

```js
import transpile from '#root/src/transpilers/2.0.0-beta/transpiler.js';

test('plot translation', async () => {
  const { lexicalErrors, syntaxErrors, translatedCode } = await transpile('Plot 10,20');

  expect(lexicalErrors.errors).toEqual([]);
  expect(syntaxErrors.errors).toEqual([]);
  expect(translatedCode).toContain("plotDiv.style.left = 10 + 'px';");
  expect(translatedCode).toContain("plotDiv.style.top = 20 + 'px';");
});
```

Run `npm test`. `translatedCode` has been formatted by prettier, so compare against the formatted
code: `(10) + 'px'` becomes `10 + 'px'`.

### Step 6: spreadsheet

Set `GRAMMAR SUPPORT`, `SEMANTIC SUPPORT` and `TESTS` to `Y` for `PLOT`.

## 4. Tutorial: add a function (`ABS`)

A function returns a value inside an expression (`X = Abs(-3) + 1`). Compared with an
instruction, there are two differences:

- the grammar rule must also be listed in `factor:`, the part of an expression a function call
  can appear in;
- the method **returns** JavaScript instead of emitting it, and is forwarded from
  `expression-visitor.js`.

The spreadsheet says: `ABS`, category Function, documented at
`https://amospromanual.dev/05-03-maths.html#fn-abs`. So it goes in `commands/functions.js`,
alphabetically before `COS`.

**Step 1: grammar.** In `grammar/amos.g4`, under `// ---- Functions ----`, before `// BTST`:

```antlr
// ABS
absFunction:
    'Abs' ROUND_BRACKET_OPEN expression ROUND_BRACKET_CLOSE
    ;
```

Add it next to the other functions in `factor:`:

```antlr
    | qcosFunction
    | absFunction
    | rndFunction
```

**Step 2:** `npm run compile-grammar`.

**Step 3: visitor.** In `expression-visitor.js`, add a line next to the other functions in
`visitFactor`:

```js
if (ctx.absFunction()) return this.visit(ctx.absFunction());
```

and the forwarder in the Functions section (A-Z, before `// COS`):

```js
  // ABS
  visitAbsFunction(ctx) {
    return this.translator.functions.visitAbsFunction(ctx);
  }
```

**Step 4: translation.** In `commands/functions.js`, before `COS`:

```js
  // ---- ABS: https://amospromanual.dev/05-03-maths.html#fn-abs ----
  visitAbsFunction(ctx) {
    return `Math.abs(${this.expr(ctx.expression())})`;
  }
```

**Step 5: test.** `X = Abs(-3)` must translate to `X = Math.abs(-3);`.

**Step 6:** update the spreadsheet.

## 5. The first command of a new category

Example: the first Interface Instruction.

1. Create `commands/interface-instructions.js` (category in kebab-case plural):

   ```js
   import BaseHandler from './base-handler.js';

   /**
    * AMOS commands of the category "Interface Instruction", sorted A-Z by AMOS name.
    * Each method is called by the forwarder with the same name in amos-translator.js.
    */
   export default class InterfaceInstructions extends BaseHandler {
     // ---- COMMAND NAME: link from the spreadsheet ----
     enterRuleName(ctx) {
       this.emit('...');
     }
   }
   ```

2. In `amos-translator.js`: import the class, create it in the constructor next to the others
   (`this.interfaceInstructions = new InterfaceInstructions(this);`), and add a section for its
   forwarders before the AMCAF section:
   `// ---- Interface Instructions (commands/interface-instructions.js) ----`.
   If the category returns values (Function, Reserved Variable…), the forwarders go in
   `expression-visitor.js` instead, as in [section 4](#4-tutorial-add-a-function-abs).
3. In `grammar/amos.g4`: add a `// ---- Interface Instructions ----` heading for its rules,
   before `// ---- AMCAF extension ----`.

Then continue as in [section 3](#3-tutorial-add-an-instruction-plot).

## 6. Modify an existing command

1. Find it: search for its name in capitals, e.g. `// ---- CLS` in `commands/`.
2. Change its method. If the AMOS syntax changes (for example a new optional parameter), change
   the rule under `// CLS` in `grammar/amos.g4` and run `npm run compile-grammar`.
3. Update the command's test in `tests/` (e.g. `tests/cls.spec.js`) and run `npm test`.

## 7. Helper reference

Inside a method of a command file:

| Helper                       | What it does                                                                  |
| ---------------------------- | ----------------------------------------------------------------------------- |
| `this.emit(code)`            | Appends JavaScript to the program body                                        |
| `this.expr(ctx)`             | Returns the JavaScript of an expression node (`''` if `ctx` is missing)       |
| `this.declareVariable(name)` | Emits `let name = 0;` (or `""` for `NAME$`) the first time a variable is used |
| `this.translator`            | The translator, for less common state (see below)                             |

Translator state used by a few commands: `colorMapping` and `palette` (`PALETTE`),
`functionDeclarationSupport`, `scopes`, `currentScope` and `globalVariablesSet` (`PROCEDURE`,
`GLOBAL`), and `hasDataMatrix` (`DATA`).

Reading the parse tree (`ctx`):

- Its methods are named after the parts of the grammar rule: `ctx.expression(0)` (the first
  expression), `ctx.expression()` (all of them), `ctx.NUMBER()`, `ctx.IDENTIFIER()`,
  `ctx.STRING()`…
- `ctx.getText()` returns the AMOS source text of the node.
- The exact list is in the rule's `Context` class in `grammar/generated/AMOSParser.js`, e.g.
  `class PlotContext`.

## 8. Pitfalls

- **Never edit `grammar/generated/`.** Change `amos.g4` and run `npm run compile-grammar`.
- **Order of `statement:`.** ANTLR picks the first alternative that matches, so append new
  commands at the end unless they must win over an existing one.
- **Keywords.** A literal in a parser rule (`'Plot'`) becomes a keyword, so a variable can no
  longer be named `Plot`. Multi-word keywords that must be a single token (`'Screen Open'`) are
  lexer rules in the Keywords section, above `IDENTIFIER`.
- **Error messages.** Adding or moving grammar rules changes the order of the
  `expecting {…}` list in syntax errors. This is expected.
- **Formatting.** The generated program is formatted by prettier, so tests must compare against
  formatted code.
- **Keep the three places in sync:** grammar, forwarder and command file, each in A-Z order with
  the `// NAME` comment.

## 9. Checklist

- [ ] Category looked up in the spreadsheet
- [ ] Grammar rule under its category heading, A-Z, with `// NAME`, and added to `statement:`
      (instructions, structures) or `factor:` (functions)
- [ ] `npm run compile-grammar`, and the `grammar/generated/` files committed
- [ ] Forwarder in `amos-translator.js` or `expression-visitor.js`, A-Z, with `// NAME`
- [ ] Method in `commands/<category>.js`, A-Z, with the marker and documentation link
- [ ] Test in `tests/<command>.spec.js`, and `npm test` passes
- [ ] Spreadsheet updated (`GRAMMAR SUPPORT`, `SEMANTIC SUPPORT`, `TESTS`)
