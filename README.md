# Reanimate-CRVJA Backend

The backend service for Reanimate-CRVJA, providing APIs to transpile AMOS BASIC, detokenize binary AMOS programs, and process AMOS sprite banks.

## How the Transpiler Works

The core transpiler relies on **ANTLR4**. A lexer and a parser, generated by ANTLR from the AMOS grammar, tokenize the AMOS BASIC code and build a parse tree. The tree is then walked and translated into JavaScript code designed to run in a web browser using HTML5 APIs.

**Adding or changing an AMOS command?** Follow the [transpiler developer tutorial](TRANSPILER.md). It explains how the `2.0.0-beta` transpiler is organized (one file per AMOS command category) and walks you through adding a command, step by step.

## Version Handling

The transpiler logic is modularized by versions: each folder in `src/transpilers/` is one version (`1.1.0`, `1.2.0`, `2.0.0-beta`). When requesting a transpilation, you can specify the target `version`; if it is missing or unknown, the `version` of `package.json` is used (currently `2.0.0-beta`). This ensures backward compatibility for older games while allowing testing of new features in newer versions.

New work happens in `2.0.0-beta`; `1.1.0` and `1.2.0` are kept unchanged.

## Getting Started

Requirements: Node.js 20 or later. Java is only needed to regenerate a parser (`npm run compile-grammar`).

1. **Install dependencies:**

   ```bash
   npm install
   ```

2. **Start the server:**
   - **Development (with hot-reload):**
     ```bash
     npm run dev
     ```
   - **Production:**
     ```bash
     npm start
     ```

   The server will run on `http://localhost:4000` by default.

3. **Run tests:**

   ```bash
   npm test
   ```

   This runs the tests in `tests/`, `src/transpilers/2.0.0-beta/tests/` and `amos-code-analysis/tests/`.

## Using the API

You can call the API locally (`http://localhost:4000`) or using your deployed production URL. `GET /` is a health check that returns `{ "status": "ok", "message": "CRVJA 🍺" }`.

### 1. Transpile Code

- **URL:** `/api/transpile`
- **Method:** `POST`
- **Body Example:**
  ```json
  {
    "code": "Print \"Hello World\"",
    "version": "2.0.0-beta"
  }
  ```
  `version` is optional. Keywords must be written as in the AMOS editor (`Print`, not `PRINT`).
- **Response:**
  ```json
  {
    "message": "(AMOS -> JavaScript) Successfully transpiled.",
    "data": {
      "lexicalErrors": { "errors": [] },
      "syntaxErrors": { "errors": [] },
      "translatedCode": "..."
    }
  }
  ```
  If the AMOS code has errors, each one is listed as `{ "line", "column", "msg" }` and `translatedCode` is empty. A missing or non-string `code` returns `400`.

### 2. Get Available Versions

- **URL:** `/api/versions`
- **Method:** `GET`
- **Response:** `{ "message": "Available versions fetched.", "versions": ["2.0.0-beta", "1.2.0", "1.1.0"] }`

### 3. Decode a binary AMOS program

- **URL:** `/api/decode-amos`
- **Method:** `POST`
- **Content type:** `multipart/form-data`
- **File field:** `file`
- **Response:** `{ "sourceCode": "..." }`
- **Upload limit:** 5 MB

The decoder validates the AMOS container, loads the packaged AMCAF token table, and returns detokenized AMOS source code.

### 4. Parse or generate an AMOS bank

- **Parse:** `POST /api/parse-bank-file` with a `.abk` file in the multipart field `file`. Returns `{ "message", "sprites", "palette" }`.
- **Generate:** `POST /api/generate-bank-file` with `sprites`, `palette`, and an optional `filename` in a JSON body. Returns the bank as a `.abk` file download.
